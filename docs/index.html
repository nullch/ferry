Возможности

Всё, что обычно забывают при переезде

Сначала разведка и план, потом перенос — с проверкой и откатом.

🔐

mTLS 1.3

Свой мини-CA. Без паролей, без root-SSH между серверами. Клиентский сертификат обязателен.

🧭

План до действий

-dry-run показывает пакеты, пользователей, службы, занятые порты и свободное место.

🌍

Разные дистрибутивы

apt, dnf/yum, zypper, pacman, apk. Имена пакетов и служб сопоставляются автоматически.

🧠

Умный /etc

Только то, чего нет в пакетах, и изменённые конфиги — сверка с dpkg, rpm, pacman, apk.

✅

Целостность

sha256 каждого файла при отправке и приёме. Права, владельцы, suid, симлинки, mtime.

♻️

Откат и повтор

Перезаписанное — в бэкап. Применение можно повторить: -resume.

Кросс-дистрибутивный перенос

Архивы

Не переезжать, а сохранить — и развернуть позже

Положите tar.gz сервера на другой сервер, а потом разверните его как перенос или просто распакуйте.

Создать

# на другой сервер
$ sudo ferry push -server backup -archive

# локально
$ sudo ferry archive -o /backup/srv.tar.gz

Развернуть

# план → подтверждение → apply
$ sudo ferry restore -archive srv.tar.gz

# только распаковать (владельцы, права)
$ sudo ferry restore -archive srv.tar.gz \
    -extract-to /mnt/restore
Быстрый старт

Пять команд

# 1. сборка (Go ≥ 1.19) или бинарник из Releases
$ make build && sudo install -m 0755 bin/ferry /usr/local/sbin/ferry

# 2. сертификаты — один раз; разложить по серверам (см. README)
$ ferry pki -dir ./pki -hosts 203.0.113.10

# 3. приёмник
$ sudo ferry serve

# 4. источник: разведка и план
$ sudo ferry scan
$ sudo ferry push -server 203.0.113.10 -dry-run

# 5. перенос и запуск служб
$ sudo ferry push -server 203.0.113.10 -start
Базы данных копируйте дампами (mysqldump, pg_dumpall) в /root/dumps до переноса — каталог уедет вместе со всем остальным.
